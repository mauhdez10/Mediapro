ROOT CAUSE DISCOVERED
---------------------

**The Problem**: Excel COM `.Value2` property has strict type conversion requirements that fail when writing PowerShell numeric values (System.Double). 

**The Solution**: Use `.Value` property instead, which handles type conversions more gracefully.

KEY TECHNICAL INSIGHTS
---------------------

1. **Excel COM Property Differences**:
   - `.Value`: Handles type conversions, accepts dates, numbers, formulas
   - `.Value2`: Strict, faster, but type-restrictive (no dates/currency)

2. **Array Type Handling**:
   - Excel COM can return `System.Object[,]` even for single cells
   - PowerShell arrays require careful unwrapping for COM interfaces

3. **Type Casting in COM Interop**:
   - PowerShell→Excel COM requires explicit type considerations
   - Numeric values need appropriate COM property selection
